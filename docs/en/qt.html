Event (QT signal) handling

1. Designer (JSON)

In the form's JSON file, events are specified using the original Qt signal names. The key is the signal name, the value is the name of the handler function in the script.

{
    "events": {
        "clicked": "qPushButton1_clicked",
        "formCloseQuery": "Form1_formCloseQuery"
    }
}
function qPushButton1_clicked(Sender, checked) {
    form.close();
}

function Form1_formCloseQuery(Sender) {
    return form.qCheckBox1.checked;
}

2. Script (dynamic connection)

To dynamically connect/disconnect handlers, use a property named after the original signal. The function name can be anything, including anonymous functions (lambdas).

widget.signalName = handlerFunction;

Examples

// Named function
function handleClick(sender, checked) {
    print("Button pressed!");
}
btn.clicked = handleClick;

// Anonymous function (lambda)
btn.clicked = function(sender, checked) {
    print("Click!");
};

// Lambda without arguments
timer.timeout = function() {
    print("Timer fired");
};

// Removing the handler
btn.clicked = null;

// Dynamically switching the handler
form.formCloseQuery = form.qCheckBox2.checked
    ? Form1_formCloseQuery
    : function(Sender) { print("lambda"); };

The first argument passed to the function is always sender (the object that emitted the signal). This is followed by the Qt signal arguments (bool, int, QString, etc.), which are automatically converted to script types.

JSON form lifecycle

Loading a RuntimeForm synchronously runs these phases:

  1. Form widgets are created and their properties are applied.
  2. The top-level code of the form's Script module is evaluated (EvalModule).
  3. Form and widget events are connected.
  4. QDbGridView tables with autoOpen: true are opened.
  5. The formCreate (OnCreate) handler is called.

This order is preserved for compatibility. A database connection needed by automatically opened tables must be completed in the top-level form code, before the autoOpen phase; connecting in OnCreate is too late. Declare named event handlers in the form code so they exist when the event-connection phase runs. In OnCreate, autoOpen tables are already open. No separate hooks or managed deferred activation are added: they would introduce new semantics and are unnecessary when the existing explicit phases are followed.

// Top-level code runs before autoOpen
db.connect(db.QSQLITE, "app.sqlite");

function formCreate(Sender) {
    // SQL grids with autoOpen have been opened by this point
    print(form.products.currentRowIndex());
}

function products_currentRowChanged(Sender, rowIndex) {
    // rowIndex is a zero-based row index
}

See QDbGridView for SQL-grid and currentRow() details.

Application example

var app = qt.app();
var mainWindow = qt.create("QMainWindow");
mainWindow.windowTitle = "My application";
mainWindow.resize(800, 600);
mainWindow.enableLayoutManager();

var central = qt.create("QWidget", mainWindow);
mainWindow.setCentralWidget(central);

var btn = qt.create("QPushButton", central);
btn.text = "Click me";
btn.align = "alTop";

var textEdit = qt.create("QPlainTextEdit", central);
textEdit.align = "alClient";

function onBtnClicked(sender) {
    dialog.showmessage("You clicked the button!");
}
btn.clicked = onBtnClicked;

var menuBar = mainWindow.menuBar;
var fileMenu = menuBar.addMenu("File");
fileMenu.addAction("Exit").triggered = function(sender) {
    app.quit();
};

mainWindow.show();
qt.run();
