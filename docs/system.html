Выполнение процессов

ФункцияОписание
system.system(cmd)Синхронное выполнение команды
system.exec(cmd, [timeoutMs])Запуск команды с захватом stdout/stderr. Возвращает {success, code, stdout, stderr}; таймаут по умолчанию 60 секунд
system.systemex(cmd, [workDir], [timeout])Скрытый запуск с рабочей папкой и таймаутом. Возвращает {success, code, killed}
system.systemasync(cmd, [workDir], [timeout], [options])Асинхронное. Возвращает объект Process. options управляет связью с консолью (см. ниже)
system.execArgvAsync(argv, [opts])Асинхронный запуск БЕЗ shell по массиву аргументов. Возвращает объект Process; по завершении result — #{"success","code","killed","stdout","stderr"}. opts: {"cwd","timeout","outfile","errfile","console"}

Необязательный аргумент options — кортеж #{"console": "..."}, управляющий связью дочернего процесса с консолью родителя:

  • "inherit" (по умолчанию) — дочерний консольный процесс может разделять консоль родителя;
  • "new" — CREATE_NEW_CONSOLE: отдельная консоль для консольного дочернего процесса (для GUI Windows игнорирует);
  • "detached" — DETACHED_PROCESS: дочерний процесс не использует консоль родителя. Рекомендуется для браузеров/долгоживущих GUI.

Пример: system.systemasync("start chrome …", "", 60000, #{"console": "detached"}). Неизвестное значение console возвращает диагностическую ошибку. Текущие вызовы без options ведут себя как раньше. Дочерний процесс без DETACHED_PROCESS/CREATE_NEW_CONSOLE может разделять консоль родителя и менять её режимы — диагностику/восстановление см. в модуле Log (Log.consoleInfo()/Log.refreshConsole()).

system.exec в текущей реализации Windows запускает команду через cmd.exe /c. При таймауте процесс завершается и success будет false; значение code при принудительном завершении не следует считать кодом завершения команды.

system.execArgvAsync(argv, opts) — асинхронный запуск БЕЗ оболочки по массиву аргументов: argv[0] — исполняемый файл, остальное — аргументы (экранирование не требуется). opts — #{"cwd","timeout"(мс),"console": "inherit"|"new"|"detached","outfile","errfile"} — как у system.execArgv. Возвращает объект Process (isReady, kill()); по завершении Process.result — #{"success","code","killed","stdout","stderr"}. stdout/stderr собираются из outfile/errfile, а если они не заданы — из временных файлов, которые создаются и удаляются автоматически. Ошибка запуска в фоновом потоке не бросается: success=false, а сообщение кладётся в stderr.

var proc = system.execArgvAsync(#[exe, "arg1", "arg2"], #{"timeout": 30000});
while (!proc.isReady) system.sleep(0.05);
var r = proc.result;
print("code=" + r.code + " out=" + r.stdout + " err=" + r.stderr);

system.getcommandline()

Возвращает кортеж:

КлючОписание
app / basename / dirname / filenameСведения об исполняемом файле (qodeqt.exe)
argv0Первый аргумент как передал shell (нормализованный)
rawВсе аргументы как есть, по порядку (raw[0] — путь к скрипту для qodeqt)
argsТолько не-флаговые аргументы (путь к скрипту — первый элемент)
countКоличество не-флаговых аргументов
flagsРазобранные флаги: --name=value, --flag, сгруппированные короткие -abc. Значение из = приводится к bool, если распознаётся (true/false/1/0/yes/no/on/off). Повторный флаг сохраняет первое значение (семантика tuple/emplace — см. библиотеку cli для явной политики)
parsedУпорядоченные токены для библиотек CLI: каждый элемент — #{"flag": имя}, #{"flag": имя, "value": строка}, #{"pos": текст} или #{"end": 1} (разделитель --, после которого всё — позиционное). Значения из = хранятся сырой строкой (приведение по типу — на стороне потребителя). parsed[0] — путь к скрипту

-- в flags/args ведёт себя как раньше (разделитель не попадает в args, последующие токены -… по-прежнему попадают в flags); корректная обработка конца флагов — через parsed. Полная схема флагов в стиле argparse — библиотека cli.
